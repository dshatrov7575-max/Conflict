# MVP7_POS_KVS_RUBRIC_V1_2_PATCH

**Статус: PROPOSAL. Версия: 1.2. Дата: 2026-09-26.**

Этот delta применяется поверх v1 и v1.1. Он исправляет только пять находок
из `MVP7_POS_KVS_RUBRIC_V1_1_HOLDOUT/ERROR_LEDGER.json`. Старые документы,
60 + 48 карточек и оба frozen keys сохраняются без изменений. Их ответы
не пересчитываются v1.2. Ни число в старой строке ключа, ни статус старого
запуска не исправляются задним числом.

| Основание v1.1 | Изменение v1.2 |
| --- | --- |
| SYN-H11-022/037/039 | P1.2-G: явно разрешённая замена оборота в форме перевеса; закрытое правило ссылки на целое R. |
| SYN-H11-042 | P1.2-D: отдельная разрешённая дательная конструкция полного несогласия; она не называется перестановкой слов. |
| SYN-H11-004 | P2.2-E/T2: отдельное предъявление и проверка понимания целого R перед intended POS 0; при отсутствии — обязательный UNKNOWN. |

## 1. P1.2 — предел разрешённых преобразований

Заменяется только абзац v1.1 §2 от «Это перечень смысловых шаблонов» до
«Новые лексические эквиваленты во время проверки не добавляются».
Таблица якорей, различение степени и риторики, личного отношения и вероятности
истинности, требования полного охвата и остальные правила сохраняются.

Таблица v1.1 задаёт закрытые языковые формы, а не открытое множество
семантически похожих реплик. Нужны одновременно: допустимая форма и все
содержательные условия соответствующего якоря. Одной близости смысла
недостаточно. Форма может быть преобразована только следующими операциями:

- Прежние операции: изменение лица, числа, рода и порядка слов; подстановка
  точного полного текста R; вставка «именно это утверждение» с однозначной
  отсылкой; перенос уже явно названного условия в другую фразу той же речи.
- **P1.2-R, ссылка:** в позиции R допускается также ровно одна однозначная
  ссылка «это предложение», «это правило» или «это утверждение» с необходимым
  склонением. В карточке должно быть единственное явно предъявленное точное
  R; ссылка должна обозначать его целиком. «Всего/всему/всем/всё» согласуется
  с этой ссылкой. Одна метка R в карточке не делает ссылку однозначной, если
  речь явно указывает на иной предмет или часть R. Нельзя заменять R словами
  «это», «решение», «вопрос» либо иной неназванной ссылкой по своему усмотрению.
- **P1.2-G, форма перевеса:** в двух формах «в отношении всего R согласие
  перевешивает несогласие, но не является полным» и «в отношении всего R
  несогласие перевешивает согласие, но не является полным» оборот
  «в отношении всего R» можно заменить на «по всему R», и обратно.
  Остальная часть формы сохраняет субъекта, направление и неполную степень.
  Местоименная ссылка на R разрешается по P1.2-R. Это разрешение конкретной
  замены оборота, а не неограниченная замена предлогов.
- **P1.2-D, P-NF:** форма «моё несогласие со всем R полное» имеет ещё один
  явно разрешённый вариант: «всему R моё несогласие полное».
  Например, слот ссылки может принимать форму «всему этому предложению».
  Здесь меняются предлог и падежное управление; это отдельное разрешение,
  а не следствие изменения порядка слов. Оно относится только к указанной
  форме полного собственного несогласия. Не разрешается автоматически
  нормализовать другие неназванные конструкции или переносить эту операцию
  на иную степень, предмет либо форму согласия.

Перечисленные операции можно сочетать. Ни одна не разрешает менять отрицание,
субъект, предмет, степень, область, модальность или время. Неперечисленная
замена оборота или лексики остаётся недопустимой даже при понятном общем
смысле: `UNKNOWN / null / FORM_NOT_LICENSED`. При неоднозначной ссылке на R:
`UNKNOWN / null / REFERENCE_AMBIGUOUS`. Это причины учебного отказа, не новые
enums продукта. Общие правила UNKNOWN/DISPUTED не изменяются.

## 2. P2.2-E — предъявленное понимание при POS 0

Требование P2 v1.1 о явном понимании точного R сохраняется. Для числового
P-Z кодер и автор intended answer отдельно указывают доступное свидетельство
каждого из следующих условий:

1. **EXPLICIT_UNDERSTANDING:** актор прямо заявляет понимание всего точного R,
   либо контекст прямо устанавливает, что этот актор понимает это R целиком.
   Ссылка на R должна быть однозначной. Доказательство понимания не заменяется
   тем, что автору/кодеру понятна формулировка R.
2. **SETTLED_NO_PREFERENCE:** собственное определённое отношение актора к
   принятию и отклонению всего R — отсутствие предпочтения; допустимая форма
   P-Z и остальные условия v1.1 сохранены.

«Прочитал R», «знает тему», «не говорит о незнании», «определил отношение»
и утверждение интервьюера в вопросе сами по себе не устанавливают первое
условие. Второе условие не подразумевает первое. Полностью предъявленный
текст R также не доказывает его понимания актором.

Если EXPLICIT_UNDERSTANDING не предъявлено, даже при явном собственном
отсутствии предпочтения: `UNKNOWN / null / UNDERSTANDING_NOT_ESTABLISHED`.
Это отказ по нехватке основания, а не вывод о том, что актор не понимает R.
POS 0 нельзя подставлять по умолчанию. Если оба условия явно предъявлены,
недостаток, найденный в 004, отсутствует; остальные общие допуски всё равно
проверяются. Правила нейтральности, безразличия, нерешённости и риторики не
переписываются.

## 3. T2 — исправление процедуры нового intended answer

Ошибка SYN-H11-004 исправляется для новых материалов проверкой полноты
основания, а не правкой frozen key. В новом ключе для каждого intended POS 0
обязательны отдельные точные цитаты/ссылки на EXPLICIT_UNDERSTANDING и
SETTLED_NO_PREFERENCE из публичной карточки. Если первого условия нет,
intended answer обязан быть UNKNOWN. Rationale не может добавлять факт
понимания. Независимый аудитор проверяет наличие обоих условий до признания
числового intended answer поддержанным.

Аналогично, для изменённых форм P1.2 ключ показывает исходную форму и
конкретные разрешённые операции. Ясность смысла не заменяет лицензии на
форму. Эти правила не гарантируют правильность нового ключа: она проверяется
независимо после его предварительной фиксации. Найденный после freeze дефект
остаётся в ключе, журнале ошибок и знаменателях.

## 4. Неизменяемая часть и граница вывода

Правила KVS v1.1 K1/K2 полностью сохраняются. Также сохраняются сетки якорей,
общий Evidence threshold, G1–G7, интерполяция, групповой/временной допуск и
прочие положения v1/v1.1, кроме прямо заменённого абзаца и уточнений выше.
Никаких изменений Core, формулы, весов или факторов не предусмотрено.

Новый HOLDOUT V2 проверяет только затронутые POS-границы -10/-5, 0/+5,
+5/+10 и формы/условия P1.2/P2.2. Успешная граница POS -5/0 и KVS не
перекодируются: прежние результаты по неизменённым правилам сообщаются
отдельно, с происхождением и ограничениями. Отдельный статус фактора не
переписывает прежний общий BLOCKED.

Статус документа остаётся PROPOSAL при любом исходе. READY означает только
допуск к будущему double-blind HUMAN pilot в пределах проверенной инструкции;
не эмпирическую валидность модели. Zhanaozen Evidence, HUMAN coding, UNO,
RGU/KVPTN, commit и PR вне этой работы.
