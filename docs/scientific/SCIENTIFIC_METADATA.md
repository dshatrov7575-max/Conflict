# Scientific Metadata — отдельный описательный слой

Версия документации: `0.1.0`. Формат метаданных: `1.0.0`.

[factors.metadata.json](factors.metadata.json) содержит описания подтверждённых
входов, а [factor-metadata.schema.json](factor-metadata.schema.json) задаёт
проверяемый JSON Schema Draft 2020-12 контракт. Это самостоятельные файлы
документации. Приложение не загружает их; они не являются конфигурацией Core,
новым Foundation package, миграцией или частью CalculationSnapshot/Run.

## Происхождение, выбор и версия

| Поле | Назначение |
| --- | --- |
| `source` | Список источников описания фактора: `kind`, `reference`, `locator`. Для реализации используется ссылка на конкретный commit и имя поля/раздела; для литературы — библиографическая ссылка; для эмпирики — проверяемый ресурс и место в нём. |
| `selection_basis` | Почему фактор включён в каталог. У текущих записей это наличие входа в существующей стратегии, а не доказательство оптимальности выбора или веса. Если основание неизвестно — null. |
| `methodology_version` | Точная версия подтверждённой методики перехода от наблюдений к оценке фактора. Сейчас null: этот слой не устанавливает и не приписывает задним числом версию рубрики. После проверки можно указать её ID и ссылку через `source`. |
| `confidence_rationale` | Обоснование научной уверенности со ссылкой на проверку. Сейчас null и `confidence_level=UNKNOWN`. Для LOW/MEDIUM/HIGH схема требует непустой текст, а содержательная проверка остаётся задачей review. |
| `baseline_commit` | Commit, по которому описаны входы; позволяет проверить ссылки на код. |
| `documentation_version` | Версия этого научного описания (`0.1.0`); не версия вычислительного алгоритма и не версия исторической кодировки. |
| `schema_version` | Версия структуры отдельного JSON-файла (`1.0.0`). |
| `model.strategy_id`, `model.strategy_version` | Описываемая исполняемая идентичность: `POLARIZATION_V1_BETA / 1.0.0`. Метаданные её не регистрируют и не изменяют. |

Основные поля онтологии определены в [Factor Ontology](FACTOR_ONTOLOGY.md).
Текущие `source` подтверждают устройство реализации. Они не выдают код за
эмпирическое исследование, а `theoretical_basis=[]` и `indicators=[]`
сохраняют отсутствие подтверждённого обоснования конкретных измерений.
Концептуальные соответствия изложены отдельно в
[Theoretical Foundation](THEORETICAL_FOUNDATION.md) со статусом `PROPOSAL`.

Допускаются источники вида `IMPLEMENTATION`, `LITERATURE`, `METHODOLOGY`,
`EMPIRICAL`. В `theoretical_basis` запись содержит `theory`, `reference`,
`relationship`, `claim_status`; в `indicators` — `name`, `definition`,
`source_reference`, `measurement_rule`. Эти массивы заполняются только при
наличии проверяемого содержания. Схема проверяет форму, не достоверность.

## Как дополнить описание

1. Выбрать существующий `factor_id` и проверить его область измерения по коду.
2. Внести источник с точным местом, отдельно указать основание выбора.
3. Если подтверждены индикатор и рубрика, записать их и версию методики.
   Неизвестное оставить null или пустым массивом; не заменять вымышленными
   значениями, нулём, примером или словом «подтверждено».
4. Для теоретической связи обозначить `PROPOSAL`, `OPEN`,
   `EXTERNAL_FOUNDATION`, `PROJECT_HYPOTHESIS` или `EMPIRICAL_RESULT` по
   фактическому статусу. Ссылка на чужую теорию не доказывает вывод формулы.
5. Повысить версию документации при изменении содержательного описания,
   сохранить предыдущий commit и пройти review. Изменение формата требует
   новой версии схемы; новый вычислительный вход — отдельного изменения метода.

Текущая схема намеренно ограничивает каталог четырьмя существующими типами
входа, каждый из которых должен встречаться ровно один раз. Шаблон будущего
фактора из онтологии не включается в этот каталог как реальные данные.

## Совместимость с историей

Метаданные не изменяют таблицы, импорт, export packages, оценки, source IDs,
версии, digest или JSON существующих снимков. `InputValue.source_id` и
`source_version` продолжают указывать происхождение конкретного числового
входа. `source` в этом документе относится к описанию типа фактора; это другой
уровень происхождения, который не подменяет исторический trace.

Для цитирования научного описания вместе с результатом можно отдельно
указать commit метаданных и `documentation_version` в исследовательском
отчёте. Это ручная ссылка, без нового поля в CalculationRun. Новая документация
не объявляет старые оценки измеренными по более поздней методике.

Локальная проверка JSON-схемы и результаты регрессии описаны в
[VALIDATION.md](VALIDATION.md).
