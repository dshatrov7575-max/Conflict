# Factor Ontology — Conflict Analysis MVP7

Версия документационного слоя: `0.1.0`. Область: входы
`POLARIZATION_V1_BETA / 1.0.0`. Машиночитаемый каталог:
[factors.metadata.json](factors.metadata.json).

## Граница онтологии

Каталог описывает четыре подтверждённых кодом типа входа. `POS` — имя
документационной записи для `ActorInput.attitude`; `KVS`, `RGU`, `KVPTN`
соответствуют одноимённым beta-входам. Эти ID не являются новыми ключами БД.
PTN и actor — объекты анализа, а `P/N/A/B/Pol/UNO` — производные показатели;
они не добавляются как независимые входные факторы.

Факт существования поля в коде подтверждён. Его валидность как измерителя
социального конструкта этим не подтверждается. Не добавляются вымышленные
факторы, наблюдения, рубрики, исторические значения или уровни уверенности.

## Поля записи

| Поле | Содержание и правило заполнения |
| --- | --- |
| `factor_id` | Стабильный ID типа входа: `POS`, `KVS`, `RGU`, `KVPTN` для текущего каталога. |
| `name` | Читаемое название, не расширяющее семантику действующего входа. |
| `description` | Что описывает вход и к какой единице анализа относится. |
| `theoretical_basis` | Список ссылок на теоретические основания с пояснением связи и её статусом. `[]` означает, что подтверждённое основание конкретной операционализации пока не внесено. |
| `indicators` | Список наблюдаемых признаков с определением, источником и правилом измерения. `[]` означает, что подтверждённый набор не внесён. Числовое поле программы само по себе не является наблюдаемым социальным признаком. |
| `measurement_notes` | Шкала и область действия из кода; правила пропусков; известные ограничения и недостающая рубрика. |
| `confidence_level` | Качественная уверенность в научном обосновании операционализации: `UNKNOWN`, `LOW`, `MEDIUM`, `HIGH`. Это не вероятность и не confidence отдельной исторической оценки. |

Все текущие записи имеют `confidence_level=UNKNOWN`. Установка другого уровня
требует содержательного `confidence_rationale` со ссылками на проверку; сам
уровень не доказывает валидацию. Он не переносится в Foundation assessment
confidence, input status или completeness расчёта. Пустые массивы не означают,
что теоретических исследований вообще не существует: они обозначают пробел
в проверенном обосновании именно этой операционализации.

Общие правила null, допустимости строки и отсутствия UNO приведены в
[Theoretical Foundation](THEORETICAL_FOUNDATION.md). Каналы и шкалы проверены по
[контрактам](../../software/conflict_analysis/calculation/contracts.py) и

Существующий [G8 import profile](../../software/conflict_analysis/docs/production-player-g8-import-profile.md)
не создаёт числовую canonical lane RGU/KVPTN: POW требует перекодирования,
а ESW методологически заблокирован. Метаданные не снимают эти ограничения.

## Шаблон будущей записи

```json
{
  "factor_id": "<ID подтверждённого фактора>",
  "name": "<подтверждённое название>",
  "description": "<конструкт и область применения>",
  "theoretical_basis": [],
  "indicators": [],
  "measurement_notes": "Метод измерения пока не подтверждён.",
  "confidence_level": "UNKNOWN",
  "confidence_rationale": null,
  "source": [],
  "selection_basis": null,
  "methodology_version": null
}
```

Это незаполненный шаблон, не запись действующего каталога. Сначала фиксируются
проверяемый источник, обоснование выбора и пробелы; затем запись проходит
методологическое review. Концептуальные предложения сохраняют статус
`PROPOSAL`; `EMPIRICAL_RESULT` требует конкретного исследования. Для нового
типа входа потребуются отдельное решение и версия метода — данная документация
не разрешает его автоматическое включение в расчёт или исторические данные.
